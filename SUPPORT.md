# Support

## Before asking for help

Check:

1. [`docs/INSTALLATION.md`](docs/INSTALLATION.md)
2. [`docs/USAGE.md`](docs/USAGE.md)
3. [`docs/COMPATIBILITY.md`](docs/COMPATIBILITY.md)
4. [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md)

## Bug reports

Use the GitHub bug report template and include:

- Power BI Desktop or Service;
- Power BI version if Desktop;
- visual version / commit when known;
- whether the bound field is Date or DateTime;
- minimal reproduction steps;
- expected vs actual behavior;
- screenshots without confidential data when useful.

Do not attach production `.pbix` files containing sensitive data. Reproduce with synthetic data whenever possible.

## Feature requests

Explain the report-author/user problem first, then the desired behavior. Features that require new Power BI privileges, network access, or changes to upstream-derived source need additional design/security review.

## Security issues

Do not use support issues for vulnerabilities. Follow [`SECURITY.md`](SECURITY.md).
