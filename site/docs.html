از دانلود فایل تا فیلتر درست داده در Power BI

این راهنما برای کاربری نوشته شده که ممکن است حتی نداند Custom Visual چیست. هر مرحله را انجام بده، خروجی را تست کن و اگر جایی مشکل بود از بخش Troubleshooting جلو برو.

دانلود PersianDatePicker.pbivizشروع آموزش

این Visual دقیقاً چیست؟

یک Date Picker شمسی برای Power BI است. کاربر در UI تاریخ Jalali انتخاب می‌کند، اما مدل Power BI همچنان روی Date یا DateTime واقعی Gregorian باقی می‌ماند.

۱۴۰۵/۰۵/۲۸← انتخاب کاربر↓2026-08-19← تبدیل انتخاب↓Power BI AdvancedFilter← فیلتر مدل
اصل مهمVisual همه‌ی ردیف‌های دیتاست را تبدیل نمی‌کند. فقط تاریخ انتخاب‌شده توسط کاربر تبدیل می‌شود.

شروع سریع برای فرد کاملاً مبتدی

  1. فایل PBIVIZ را دانلود کن. این همان فایل قابل نصب Visual است.
  2. Power BI Desktop را باز کن.
  3. Visual را Import کن. Visualizations → ... → Import a visual from a file.
  4. Visual را روی Canvas قرار بده.
  5. یک ستون Date/DateTime واقعی به آن بده.
  6. روی Date Picker کلیک کن و یک تاریخ شمسی انتخاب کن.
  7. با یک Table کنار آن تست کن که رکوردهای همان روز فیلتر شده باشند.
اگر فقط همین سناریو را داریو ستونت واقعاً Date/DateTime است، همین ۷ مرحله برای استفاده کافی است.

پیش‌نیازها

  • Power BI Desktop یا محیطی که Custom Visual را پشتیبانی کند.
  • فایل PersianDatePicker.pbiviz.
  • یک ستون مدل با Data Type برابر Date یا Date/Time.

چطور نوع ستون را چک کنم؟

در Data view یا Model view ستون را انتخاب کن و در Column tools، Data type را ببین. اگر Text است، به بخش آماده‌سازی داده برو.

PersianDatePicker.pbiviz را دانلود کن.

  1. Report را باز کن.
  2. در Visualizations روی ... بزن.
  3. Import a visual from a file را انتخاب کن.

  5. بعد از Import، Visual جدید در پنل ظاهر می‌شود.

۳. قرار دادن روی صفحه

روی آیکن Visual کلیک کن یا آن را به Canvas اضافه کن. در این مرحله هنوز Date Picker داده‌ای ندارد و باید Field تاریخ را اختصاص بدهی.

چه ستونی را باید به Date Picker بدهم؟

ستونی را بده که واقعاً باید Filter Context گزارش را هدایت کند.

مدل ساده

Sales[SaleDate] : Date

همین ستون را مستقیم بده.

مدل ستاره‌ای

DimDate[Date] : Date

معمولاً انتخاب بهتر برای چند Fact.

اشتباه رایجستون 1405/05/28 که Data Type آن Text است، Date محسوب نمی‌شود.

اختصاص دادن Field به Visual

  1. Visual را روی Canvas انتخاب کن.
  2. از پنل Data، جدول موردنظر را باز کن.
  3. ستون تاریخ را پیدا کن.
  4. آن را Drag کن و داخل Field با عنوان Date قرار بده.
Orders[OrderDate]  →  Persian Date Picker / Date

Visual در runtime نوع Field را بررسی می‌کند. اگر Date/DateTime نباشد، به‌جای تقویم پیام خطا می‌بینی.

اولین تست صحیح

یک Table Visual کنار Date Picker بساز و این فیلدها را داخلش بگذار:

تست مرجعانتخاب ۱۴۰۵/۰۵/۲۸ باید روز Gregorian متناظر 2026-08-19 را هدف بگیرد.

تقویم با Jalali DateObject کار می‌کند. بعد از تایید کاربر، انتخاب به روز Gregorian متناظر تبدیل و برای ساخت Filter استفاده می‌شود.

DateTime و رکوردهای دارای ساعت

فرض کن داده‌ها این‌طورند:

2026-08-19 00:01:00
2026-08-19 13:42:10
2026-08-19 23:59:59
2026-08-20 00:00:00

فیلتر روز 19 آگوست این است:

DateColumn >= 2026-08-19T00:00:00.000Z
AND
DateColumn <  2026-08-20T00:00:00.000Z

سه رکورد اول داخل روز هستند و رکورد چهارم نیست. این طراحی از Equality روی midnight امن‌تر است.

اگر دیتای من Text یا فقط شمسی است چه کنم؟

حالت ۱ — Gregorian Text

"2026-08-19"  (Text)

در Power Query از Transform data، Data Type ستون را به Date/DateTime تبدیل کن و conversion errors را بررسی کن.

حالت ۲ — فقط Jalali Text

"1405/05/28"  (Text)

این ستون را مستقیم به Picker نده. ابتدا یک ستون Gregorian واقعی در Source/ETL/Data Warehouse/Power Query بساز.

Jalali Text → validated conversion → Gregorian Date → Power BI Model

ترتیب پیشنهادی:

  1. Gregorian Date از Source System.
  2. تبدیل در ETL/Data Warehouse.
  3. تبدیل در Power Query با تابع تاییدشده سازمان.
چرا خود Visual Text را parse نمی‌کند؟Data Preparation و UI Filtering دو مسئولیت جدا هستند. این تفکیک جلوی ambiguity، locale bug و relationship ضعیف را می‌گیرد.

بهترین حالت: اتصال به DimDate

                 DimDate[Date]
                    │
          ┌─────────┼──────────┐
          ▼         ▼          ▼
        Sales     Orders    Payments

اگر Relationshipهای مدل درست باشند، یک Date Picker روی DimDate[Date] می‌تواند Filter Context را به چند Fact منتقل کند.

ستون‌های شمسی اضافی برای Label یا گزارش می‌توانند وجود داشته باشند، اما برای عملکرد Picker اجباری نیستند.

اگر یک جدول چند تاریخ دارد

Orders[CreatedAt]
Orders[PaidAt]
Orders[DeliveredAt]

باید تصمیم بگیری Date Picker کدام مفهوم بیزنسی را فیلتر کند. Visual نمی‌تواند این تصمیم را از نام جدول حدس بزند. در مدل‌های پیچیده ممکن است Role-playing Date Dimension لازم باشد.

تعامل با Chart/Table/KPIهای دیگر

اگر Date Picker تغییر کرد ولی یک Chart تغییر نکرد:

  1. Relationship مسیر فیلتر را بررسی کن.
  2. از Format → Edit interactions مطمئن شو Interaction غیرفعال نشده.
  3. Page/Report filter متناقض را بررسی کن.
  4. مطمئن شو Visual مقصد از همان مدل/مسیر تاریخی استفاده می‌کند.

پاک‌کردن تاریخ

بعد از انتخاب، کنترل Clear ظاهر می‌شود. Clear فیلتر متعلق به Date Picker را حذف می‌کند و مقدار UI را خالی می‌کند. فیلترهای دیگر گزارش دست‌نخورده می‌مانند.

Bookmark و Restore

Visual هنگام update، فیلتر Power BI را می‌خواند و مقدار نمایش‌داده‌شده را با Filter State هماهنگ می‌کند.

تست Bookmark

  1. یک تاریخ انتخاب کن.
  2. Bookmark با Data state بساز.
  3. تاریخ دیگری انتخاب کن.
  4. Bookmark اول را Restore کن.
  5. هم گزارش و هم تاریخ روی Picker باید برگردند.

Power BI Service

بعد از Publish، رفتار Custom Visual ممکن است تحت Tenant policy سازمان باشد. اگر در Desktop کار می‌کند ولی در Service نه، Tenant settings، Custom Visual policy و capability محیط را بررسی کن.

DirectQuery و Import

Date Picker خودش API دیتاسورس را صدا نمی‌زند. فقط Filter را به Power BI می‌دهد.

در DirectQuery، انتخاب ممکن است باعث query جدید به Source شود. Performance به مدل، Query Folding، index و Source بستگی دارد. در Import، Filter روی مدل Import شده اعمال می‌شود.

RLS

Picker RLS را دور نمی‌زند و Security Boundary نیست. RLS باید در مدل تعریف شود؛ Picker فقط داده‌ای را که کاربر از قبل مجاز به دیدن آن است محدودتر می‌کند.

چرا Calendar در Modal Dialog باز می‌شود؟

Popupهای معمولی Custom Visual ممکن است با اندازه viewport Visual بریده شوند. این پروژه از Power BI Modal Dialog API استفاده می‌کند تا Calendar مستقل از اندازه کادر Visual باز شود.

اگر محیط اجرا Modal Dialog را پشتیبانی نکند، Visual Warning نشان می‌دهد. این مورد را مخصوصاً در Embedded/Publish-to-web/Dashboardهای خاص بررسی کن.

امنیت و حریم خصوصی

  • Web privilege ندارد.
  • AAD privilege ندارد.
  • Storage privilege ندارد.
  • تبدیل تاریخ داخل runtime انجام می‌شود.
  • CodeQL و production dependency audit در CI اجرا می‌شوند.

برای جزئیات فنی: SECURITY.md و Threat Model.

تحویل به کاربر نهایی

روش ساده

فایل PBIVIZ را به کاربر بده و همین راهنمای نصب را لینک کن.

برای سازمان

اگر قرار است تعداد زیادی کاربر استفاده کنند، انتشار کنترل‌شده به‌عنوان Organizational Visual در Power BI tenant گزینه مناسب‌تری است.

چک‌لیست قبل از تحویل

  • Field نوع Date/DateTime دارد.
  • یک روز با Table مرجع تست شده.
  • DateTimeهای دارای ساعت تست شده.
  • Clear تست شده.
  • Bookmark تست شده، اگر استفاده می‌شود.
  • Edit interactions بررسی شده.
  • Service و RLS تست شده، اگر کاربرد دارد.

رفع خطا

Date Picker غیرفعال است

یک Field معتبر Date/DateTime اختصاص نداده‌ای.

پیام فیلد باید Date یا DateTime باشد

ستون Text/Number است. Data Type مدل را اصلاح کن.

تاریخ انتخاب می‌شود ولی Chart تغییر نمی‌کند

Relationship، Edit interactions و Filter Pane را بررسی کن.

Calendar باز نمی‌شود

Modal Dialog capability/محیط اجرا را بررسی کن و Power BI Desktop را به‌روز کن.

رکوردهای دارای ساعت اشتباهند

نسخه فعلی از بازه start تا next-day استفاده می‌کند. فایل release فعلی را نصب و با Table مرجع تست کن.

Bookmark مقدار را برنمی‌گرداند

مطمئن شو Bookmark شامل Data state است و Filter دیگری روی همان ستون تضاد ایجاد نمی‌کند.

سوالات پرتکرار

خروجی میلادی یعنی چه؟

Visual ستون جدید تولید نمی‌کند؛ انتخاب شمسی را به Gregorian day boundaries تبدیل و به Filter Power BI اختصاص می‌دهد.

ستون شمسی جدا لازم است؟

خیر؛ اگر Date/DateTime Gregorian واقعی داری، همان کافی است.

Text شمسی را مستقیم می‌گیرد؟

خیر. اول Data Preparation.

Range دارد؟

Scope فعلی Single Day است؛ Range می‌تواند در نسخه آینده اضافه شود.

داده را به اینترنت می‌فرستد؟

Visual Web/AAD/Storage privilege درخواست نمی‌کند.
